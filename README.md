# 영양 관리 프로그램 (yamyamprog)

20대 남성을 대상으로, **목적(운동 / 다이어트)에 맞는 일일 추천 영양소를 계산**하고
직접 입력한 식단 기록과 **비교·분석**해 주는 터미널(TUI) 기반 영양소 트래커입니다.

- 별도 설치 없이 **파이썬 표준 라이브러리만** 사용
- 서버·DB 없이 **로컬 JSON 파일**에 기록 저장
- 키보드만으로 입력 · 조회 · 수정 · 삭제 · 분석

---

## 실행 방법

**필요 환경:** Python 3.x (외부 패키지 없음)

```bash
git clone https://github.com/bangram9619/yamyamprog.git
cd yamyamprog
python main.py        # Windows: py main.py
```

> `config.json`과 `data/` 경로는 실행 위치 기준이므로, 반드시 `yamyamprog` 폴더에서 실행하세요.
> 화면 지우기(`cls` / `clear`)가 동작하려면 IDLE이 아닌 **터미널**(명령 프롬프트, PowerShell, VS Code 터미널 등)에서 실행하세요.

## 주요 기능

| 메뉴 | 기능 | 설명 |
|---|---|---|
| 1 | 모드 설정 | 운동 / 다이어트 중 목적을 선택하고 `config.json`에 저장 |
| 2 | 영양소 기록 저장 | 식단명과 탄수화물 · 단백질 · 지방 · 칼로리를 입력해 오늘 파일에 저장 |
| 3 | 영양 기록 조회 / 수정 / 삭제 | 날짜별 식단 목록과 당일 합계를 표로 보여주고, 식단 번호로 수정 · 삭제 |
| 4 | 영양 비교 분석 | 추천량 대비 섭취량을 **하루 / 최근 7일** 기준으로 비교, 텍스트 막대그래프와 판정 표시 |

### 분석 화면 예시

```
[ 모드별 기준 vs 사용자 섭취 영양 비교 분석 (하루 기준) ]
(대상 기준: 운동 모드 / 20261008 당일 누적 데이터 합산 기준)

탄수화물  [■■■■■■■■□□]  80% (  300 /   375 g) -> [부족] 탄수화물 ▲
단백질    [■■■■■■■■■□]  92% (  110 /   120 g) -> [적절] 단백질 =
지방      [■■■■■■■■□□]  88% (   60 /    68 g) -> [적절] 지방 =
칼로리    [■■■■■■■■■□]  93% ( 2400 /  2590 kcal) -> [적절] 칼로리 =
```

### 판정 기준

| 섭취 비율 | 판정 | 표시 | 의미 |
|---|---|---|---|
| 85% 미만 | 부족 | ▲ (빨강) | 추가 섭취 권장 |
| 85% 이상 ~ 110% 이하 | 적절 | = (초록) | 유지 |
| 110% 초과 | 과다 | ▼ (노랑) | 조절 필요 |

## 추천 영양소 계산

추천 영양소는 코드에 고정하지 않고, `config.json`의 **체중**과 **모드별 체중 1kg당 g** 값으로 계산합니다.

```
탄수화물 / 단백질 / 지방 (g) = 체중 × 체중 1kg당 g      → 정수로 반올림
칼로리 (kcal)               = 탄 × 4 + 단 × 4 + 지 × 9 → 10kcal 단위 반올림
```

| 모드 | 탄수화물 | 단백질 | 지방 | 75kg 기준 결과 |
|---|---|---|---|---|
| 운동 | 5.0 g/kg | 1.6 g/kg | 0.9 g/kg | 375g / 120g / 68g · **2,590 kcal** |
| 다이어트 | 3.0 g/kg | 1.8 g/kg | 0.7 g/kg | 225g / 135g / 53g · **1,910 kcal** |

일주일 분석의 목표값은 하루 목표값 × 7입니다.

### 근거 자료

- 보건복지부 · 한국영양학회, **2025 한국인 영양소 섭취기준(KDRI)** — 19~29세 남성 기준을 기본 기준점으로 사용
- Jäger R. et al., **ISSN Position Stand: Protein and Exercise (2017)** — 운동 목적에 따른 체중당 단백질량과 영양소 비중 설정에 참고

## 폴더 구조

```
yamyamprog/
├── main.py                 # 시작점 (frontend.screens.main 실행)
├── config.json             # 설정 + 추천 영양소 기준값
├── data/                   # 날짜별 식단 기록 (자동 생성, git 제외)
├── backend/                # 계산 · 저장 (화면 출력 없음)
│   ├── config.py           #   config.json 읽기 / 저장, 없거나 깨지면 기본값 복구
│   ├── storage.py          #   식단 JSON 파일 찾기 · 읽기 · 저장, 하루 / 7일 합계
│   └── nutrition.py        #   추천 영양소 계산, 부족 / 적절 / 과다 판정
└── frontend/               # 화면 · 입력
    ├── display.py          #   화면 지우기, 한글 폭 정렬, 막대그래프, 결과 한 줄 출력
    └── screens.py          #   메뉴 화면 (모드 설정, 기록, 조회 · 수정 · 삭제, 분석)
```

**설계 원칙:** `print` / `input`이 있는 코드는 `frontend`, 없는 코드는 `backend`에 둡니다.

```
사용자 → frontend (메뉴 · 입력) → backend (계산 · 저장 · 판정) → frontend (결과 · 그래프) → 사용자
```

## 데이터 형식

### `config.json`

| 키 | 자료형 | 설명 | 예시 |
|---|---|---|---|
| `lastMode` | string | 마지막으로 선택한 목적 (다음 실행 시 유지) | `"운동"` |
| `weight` | number | 추천량 계산 기준 체중 (kg) | `75` |
| `dataDir` | string | 식단 기록 저장 폴더 | `"./data"` |
| `kcalPerGram` | object | g당 칼로리 (탄 / 단 / 지) | `{"carbs": 4, "protein": 4, "fat": 9}` |
| `modes` | object | 모드별 체중 1kg당 g | `{"운동": {"carbs": 5.0, ...}}` |

`config.json`이 없거나 형식이 깨지면 기본값으로 자동 생성되고, 빠진 항목은 기본값으로 채워집니다.

### `data/YYYYMMDD_HHMMSS.json` (일일 식단 기록)

하루에 하나의 파일이 생기며, 식단 번호(문자열)를 키로 저장합니다.

```json
{
    "1": { "meal": "밥, 김치, 고등어", "carbs": 70, "protein": 35, "fat": 15, "calories": 555 },
    "2": { "meal": "닭가슴살, 현미밥", "carbs": 45, "protein": 35, "fat": 8, "calories": 392 }
}
```

## 예외 처리

| 상황 | 동작 |
|---|---|
| 식단명을 비워 둠 | 다시 입력 요청 |
| 영양소에 음수 · 문자 · 소수 입력 | "0 이상의 숫자로 입력해주세요." 후 다시 입력 요청 |
| 날짜 형식이 YYYYMMDD가 아님 | 오류 안내 후 이전 메뉴로 |
| 조회할 날짜에 기록 없음 | "기록된 식단이 없습니다. 새로 등록해 주세요." |
| 존재하지 않는 식단 번호로 수정 · 삭제 | "존재하지 않는 식단 번호입니다." |
| 분석할 날짜에 기록 없음 | 섭취량을 0으로 계산해 모든 영양소를 [부족]으로 표시 |
| 목적(모드)이 설정되지 않음 | "목적을 먼저 설정하세요." |
| `config.json` 없음 / 깨짐 / 항목 누락 | 기본값으로 생성 · 복구 |
